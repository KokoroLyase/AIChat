# 智信 AIChat

安卓端 AI 伴侣聊天应用：界面风格接近安卓版微信，聊天对象是你自己创建的 AI 联系人。没有账号和开发者服务器，数据保存在本机；聊天请求只发给你自己配置的模型服务商，语音消息（0.7.0 起）只发给你自己配置的语音合成、识别服务商，0.7.1 起也可以选本机的系统语音合成和离线识别，这时文字和录音不离开手机。0.8.0 起可以和联系人语音通话，0.9.0 起可以多选、收藏、引用和翻译消息，0.9.1 换了新图标，统一了动画和大字体、窄屏下的界面。

> 本项目与腾讯、微信没有任何关系。界面只参考布局与配色，不使用微信的图标、素材和名称。

## 安装与升级

从 [Releases](https://github.com/KokoroLyase/AIChat/releases) 下载 `AIChat-<版本号>.apk`，同目录的 `.sha256` 是校验文件。

- **覆盖安装**保留数据。所有正式版使用同一个签名；不能降级覆盖。
- **卸载会清空全部本地数据**，卸载前请先导出。
- **应用内更新：** 0.3.0 起可在 App 内下载，校验 SHA-256、包名、版本和签名后拉起系统安装；失败时可在浏览器打开发布页。0.2.0 及更早只能走浏览器。
- **自动检查：** 启动时静默检查 GitHub 最新 Release，24 小时最多一次，可在“我 → 关于 APP”关闭。

## 备份与恢复

路径：我 → 数据管理（0.4.1 是设置 → 数据）。系统自动备份已关闭，换机只能用导出和恢复。

| | 不设密码 | 设密码 |
| --- | --- | --- |
| 文件 | 普通 `.zip`，拿到文件的人都能打开 | `.aichat`，整个文件加密（分块 AES-256-GCM，PBKDF2-SHA256 31 万次） |
| API Key | 不导出，恢复后要重新填写 | 可以选择导出；包含 Key 时必须设密码 |
| 忘记密码 | 不涉及 | **无法恢复**，没有找回方式 |

- 导出内容：联系人、聊天记录、记忆、用量统计、服务商、头像、聊天图片、聊天背景（0.4.2 起）、全局记忆和回复偏好（0.5.0 起）、语音消息和语音服务商（0.7.0 起）、语音通话（0.8.0 起，每一句的文字和录音放在备份的 `calls/` 目录，跟着“聊天记录”）、收藏（0.9.0 起，单独一项，录音在 `favorites/` 目录；消息的引用和译文跟着“聊天记录”）和部分设置。还没送达的回复按已送达写入，恢复后不会再送一次。
- 选择内容（0.7.2 起）：导出时可以只选其中几项：联系人、聊天记录、联系人记忆、用量统计、全局记忆、模型配置、回复偏好、主动聊天设置、语音消息设置、个人资料和外观（0.9.0 起还有收藏，不依赖联系人），默认全选。聊天记录、联系人记忆和用量统计跟着联系人走；API Key 只跟着模型配置导出。只导出联系人、不导出模型配置时，文件里只记联系人用的服务商的格式和地址（不含 Key），恢复时按它找本机的同一个服务商，找不到时改用本机第一个服务商并提醒重新选模型。恢复时也可以只选文件里有的某几项；没选的内容本机原样保留。0.7.2 导出的文件 0.7.1 及更早的版本打不开（提示先升级），不会被当成完整备份。
- 恢复全局记忆：「覆盖」时用备份里的（0.7.2 起不想换就在恢复内容里不选全局记忆；0.7.1 及更早是先问你保留哪一份）；「合并」按创建时间认同一个类别和主题，保留本机的名称和顺序，同一主题下内容相同的记忆不重复。回复偏好覆盖时用备份里的，备份里没有时和合并时都保留本机的。
- 恢复方式：「合并」保留本机已有数据，「覆盖」先清空再导入（0.7.2 起只清空选中的内容；替换联系人时本机联系人连同他们的聊天记录和记忆一起删除，没选用量统计时本机的用量并入“已删除的联系人”）。恢复前自动做快照，失败时回滚，成功后立即删除快照和解密临时文件。
- 旧备份：明文 zip 和只加密 Key 的旧备份都能恢复，v1～v9 会逐版自动迁移到当前格式；0.4.1 及更早的备份恢复后默认不免打扰、没有聊天背景；0.4.2 及更早的备份恢复后联系人默认使用全局记忆和回复偏好，原来的分条显示设置保留。
- 主动聊天（0.6.0 起）：备份包含联系人的主动聊天开关和频率、免打扰时段和每日调用上限；今日已用次数、暂停状态、约好的提醒和上次主动请求的结果只属于这台手机，不导出，覆盖恢复也不改今日已用次数。0.5.0 及更早的备份恢复后，联系人的主动聊天都是关闭的，不会有后台调用；恢复 0.6.0 的备份后，备份里开着的联系人仍然开着，后台任务会按恢复后的数据注册。
- 语音消息（0.7.0 起）：语音文件放在备份的 `voice/` 目录，转写文字随消息；联系人的消息发送类型、音色和语气风格（0.7.2 起还有单独选的语音来源和单独设置的回复偏好，单独选的服务商恢复后指向本机的同一个，找不到时改回跟随全局；本机来源只认对应的一类，合成是系统语音、识别是离线识别，别的改回跟随全局），语音合成和识别服务商（Key 和大语言模型的一样默认不导出）和选用哪一家都随备份。还在合成的语音回复按文字写入。恢复时缺了文件的联系人语音改成文字显示，自己的语音保留转写文字。0.6.0 及更早的备份恢复后联系人都用全局的消息发送类型；覆盖恢复这类备份时，本机已配的语音服务商和语音设置保留。0.7.1 没有改备份格式：选用的本机来源（系统语音、离线识别）随备份恢复，但离线识别模型和系统音色不在备份里：恢复到另一台手机后，离线识别要重新下载模型才能用（下好之前按“没有可用的语音识别”处理），系统语音先用那台手机引擎的默认中文音色（没有不联网的中文音色时不可用）。0.7.0 读到这类来源按没有选处理。
- 版本差异：比当前 App 新的备份会被拒绝；0.3.1 读不了 `.aichat` 文件。0.7.2 的备份带核心记忆（见下面的长期记忆），旧备份的记忆恢复后都是近期记忆。0.8.0 的备份内层是 v9（多了通话），0.7.2 及更早打不开；0.7.2 的备份在 0.8.0 照常恢复。0.9.0 的备份内层是 v10（多了收藏、引用和译文），0.8.0 及更早打不开；0.8.0 的备份在 0.9.0 照常恢复，没有收藏项。合并恢复时，引用的原消息和收藏的来源联系人能对上就重新对应，对不上时只显示存下的内容。导出时正在通话的，按导出时已经说过的部分写成一次结束的通话。

App 自己加密的只有 API Key 和设了密码的导出文件。手机上的数据库、图片和设置依靠系统的应用隔离和全盘加密，App 没有另外加密。

## 功能

### 聊天

| 功能 | 说明 |
| --- | --- |
| 三个 Tab | 智信（聊天列表）、通讯录、我（个人资料；0.9.0 起个人资料下面单独一组“收藏”；全局记忆、回复偏好、主动聊天、语音消息四个入口，四个设置入口）；可左右滑动切换 |
| 接收回复 | 回复完成后整条出现，不逐字显示；请求交给 WorkManager，离开聊天页或切到后台也会继续 |
| 可靠投递（0.5.0 起） | 模型回复后各条先保存为“待投递”，由单独的投递任务按时间逐条送达；送达时才更新聊天列表预览、未读和通知（同一次回复只响一次，后几条只更新内容）。切到后台时，如果还有没到时间的条目要等，投递和等待回复一样以前台任务继续，要等得较久时会看到“正在接收消息”；都已到时间时直接送达。App 被关掉后重新打开，到时间的直接送达、没到的按原定时间接着送，不丢也不重复。联系人还在一条条发时你又发消息：已生成的先发完，再回复新消息，发给模型的最后一条一定是你的消息；“取消”只取消还没生成的请求 |
| 回复偏好（0.5.0 起） | 我 → 回复偏好：等你说完再回（默认 1 秒内没有新消息）、每轮 1～3 条、每条 16 字左右、条与条间隔 2～4 秒（按字数估算打字时间，第一条扣掉生成用掉的时间）、默认去掉每条末尾的“。”和“，”（保留“？”“！”“…”）。条数和字数写进提示词作为风格引导，按换行拆条、去标点和间隔由 App 处理；模型没按要求换行、某一条超过每条字数两倍时，在句末断开再把短句合并到接近每条字数（不在逗号处拆，有代码块时不拆）；超过最多条数时多出来的接在最后一条，字数不截断。0.7.1 及更早全局一份，联系人只有“使用回复偏好”开关；**0.7.2 起**联系人可以选跟随全局、单独设置一套或不使用，单独设置的不受全局改动影响 |
| 主动聊天（0.6.0 起） | **默认关闭**，在联系人的“朋友资料”里逐个开启，可选频率：偶尔、适中（默认）、频繁。开启后联系人会在你没有操作时自己来找你：WorkManager 周期任务大约每 15 分钟检查一次（回到 App 时也查一次），按频率、距上次互动多久和时段算一个概率，掷中后把人设、记忆、全局记忆和预算内的聊天记录发给服务商，末尾加一条只在这次请求里、不保存的提示，让模型决定发什么，或只回 `[SKIP]` 表示不发。**会自动消耗 API 额度**：模型决定不发、请求失败也各算一次，失败不重试、不通知；一次请求最多等模型 4 分钟。这些情况直接跳过、不调用模型：免打扰时段（默认 23:00～7:00，可跨午夜）、当天调用次数到上限（默认 20 次，所有联系人合计，按本地日期重置）、连续 2 次主动发送没有得到回复（你再发消息后恢复）、正在等这个联系人回复或上一轮还没送完、你正在看这个聊天、没有可用的 API Key、模型配置无效。主动消息和普通回复一样按回复偏好分条、带间隔，经同一套投递送达并发通知；聊天开了“消息免打扰”时照常主动发，只是不弹通知；不能“重新生成”。请求期间你发了消息，这次主动内容作废，先回复你。我 → 主动聊天：免打扰时段、每日上限，以及今日已用、最近检查时间、后台任务是否注册、每个联系人是否暂停及原因、上次主动请求的时间和结果。**不保证准时**：不用精确闹钟、不申请新权限，系统省电或限制后台、App 被强制停止时可能很晚才来或不来 |
| 约定时间（0.6.0 起） | 只对开启主动聊天的联系人：系统提示词多一段说明，让模型在你约了时间（“明早 7 点叫我”）时在回复末尾加一行隐藏标记，App 去掉标记、记下时间，到点用一次性后台任务发起主动请求。约好的提醒不受免打扰时段、暂停、正在看这个聊天和概率限制，仍占每日次数；同样不保证准时，晚了超过 12 小时不再发；关闭主动聊天、清空或删除聊天、删除联系人时一并去掉 |
| 分条显示 | 没开回复偏好（0.7.2 起是回复偏好选“不使用”）的联系人沿用：回复里有空行时拆成多条，约 1 秒一条依次出现；每个联系人可关闭 |
| 思考过程 | 可折叠显示，历史思考不回传给模型 |
| 图片 | 系统照片选择器（一次最多 9 张）或系统相机；压缩到长边 2048 像素并去掉 EXIF；只有最近 3 张带原图，模型不支持图片时入口不可用 |
| 消息操作 | 长按复制、删除、重新生成（最后一条回复）、取消回复；失败消息点红色感叹号重试。0.9.0 起还有多选、收藏、引用、翻译，通话消息也能复制（这次通话的时间、时长和每一句）。菜单的格子等宽，每行最多 5 项、各行项数尽量均匀，左右离屏幕边缘留出空隙；键盘开着时长按消息，键盘不收起，点菜单外面或按返回只关菜单 |
| 多选（0.9.0 起） | 长按点“多选”：每条左边出现勾选圈，点整行切换；顶栏“已选 N 条”和“取消”，底部复制、收藏、删除。复制按时间每条一行（换行变空格，图片写“[图片]”，语音写转写，通话展开成完整内容）；删除先确认，和逐条删除一样连同录音、通话的每一句一起删，会话预览刷新一次。等待回复中的消息和正在进行的通话不能选 |
| 收藏（0.9.0 起） | 长按文字、语音（含没有转写的）、打完的通话点“收藏”，多选也能批量收藏；图片和等待中的不能。收藏单独存一份（语音和通话的录音复制到 `files/favorites`），删除原消息、清空聊天、删除联系人都不影响。我 → 收藏：按收藏时间倒序，显示来源和预览（语音可直接播放，通话显示时长和前两句），可以搜索文字、转写、通话里的话和联系人名字；长按复制、删除；点开是详情（文字可选中复制，通话可以播放完整通话和每一句） |
| 引用（0.9.0 起） | 长按发送成功的文字或有转写的语音（双方的都可以）点“引用”：输入栏上方出现引用条（× 取消），下一条文字或语音带上它，发图片不带、引用条保留；通话中没有引用。气泡下面显示“名字：内容”（最多两行），点它跳到原消息并高亮，原消息已删时提示。发给模型时这条消息前面多一行“（回复你之前说的“……”）”或“（接着我之前说的“……”）”，被引用的话最多 100 字；没有引用的请求和 0.8.0 一样 |
| 翻译（0.9.0 起） | 长按文字或有转写的语音点“翻译”（只有表情、数字、标点的没有）：汉字超过一半翻成英语，否则翻成中文。用这个联系人的聊天模型和参数，能关思考就关，只发翻译提示和这条文字。译文存在消息上，显示在气泡下面并标“翻译”，长按可复制、隐藏，再点“翻译”直接显示不再请求；正在翻译、失败（显示原因，点一下重试）都有提示。译文不进上下文和记忆，多选复制只复制原文 |
| 发语音（0.7.0 起） | 输入栏最左边切到“按住 说话”：按住录音，最长 60 秒（最后 10 秒倒数，到时自动结束），不到 1 秒提示太短；松开发送，上滑到左边取消、右边转成文字放进输入框。读屏时可以点一下开始、再点发送，另有取消和转文字操作。第一次使用时说明录音会发给哪个语音识别服务商（0.7.1 起用离线识别时说明录音不离开手机），并申请麦克风权限（拒绝后说明并给出系统设置入口）。发出后先显示语音条，回复任务**先识别再请求模型**：识别成功后转写文字作为这条消息发给模型，录音压成 AAC 保存；识别失败（或没设置语音识别）时这一轮标为失败、不请求模型，点感叹号重试会重新识别 |
| 录音转文字（0.7.0 起） | 输入框里的麦克风按钮：点一下开始录，点“完成”识别，结果插到光标处，改完再发；录音不保留 |
| 收语音（0.7.0 起） | 消息发送类型决定联系人回文字还是语音：跟随（默认，你发语音回语音、发文字回文字，看这一轮等待回复的最后一条）、文字、语音（总是回语音，主动消息也是；跟随和文字模式下主动消息发文字）。在“我 → 语音消息”设全局默认，联系人可以单独指定。回语音时先生成文字、存库，按长度分成 1～2 条（很长时按句子分成多条，每条不超过 300 字）逐条合成，合成好才送达；某条合成失败就那条改发文字，全部失败时按回复偏好重新拆成文字消息，都不再请求模型。没设置语音合成时一律回文字。取消回复时还没合成的改成文字送达 |
| 语音条（0.7.0 起） | 自己绿色、对方白色，宽度随时长变化，显示秒数，播放时声波动画；对方没听过的旁边有红点，有转写文字时旁边有“转文字”，展开后文字显示在语音下面；自己的语音识别出文字前显示“正在识别…”。点一下播放、再点停止；放完对方没听过的会接着放下一条没听过的。长按：复制（转写文字）、删除、听筒播放、后台播放（回到桌面也接着放，显示一条不含内容的常驻通知）、转文字或取消转文字、连续朗读（从这条起依次放完后面的语音）。离开聊天页时停止（后台播放除外）；被来电或别的 App 的声音打断时停止。语音在聊天列表和通知里显示为“[语音]”，搜索能搜到转写文字 |
| 语音通话（0.8.0 起） | 联系人资料“发消息”下面、聊天页“+”里“相册”“拍照”后面的“语音通话”。用这个联系人实际的语音识别和合成来源（单独选的用不了时不能打，不换成全局的；系统语音和离线识别也能用），发起前检查来源、Key、是不是还在回上一条；第一次通话前说明录音和文字发给谁，然后要麦克风权限。**半双工**：在听时判断你是否在说话（随安装包的 Silero VAD 模型，不支持的手机按音量判断），静音约 0.8 秒算说完，不到 0.3 秒的不算，一段最长 25 秒；说完就识别，把文字和预算内的聊天记录发给联系人的模型（系统提示词多一段“现在是语音通话、口语简短”），回复边生成边按句合成、按顺序播放，放完再听；联系人说话时不听，可以点“打断”，你在说时可以点“说完了”。通话接在原聊天后面，不新开上下文，之后的上下文、自动记忆和搜索按每一句展开。失败时提示后接着听，不自动重试；连续 3 轮失败、单次 60 分钟（提前 5 分钟提醒）、5 分钟没人说话、来电、麦克风出错时自动挂断。返回键不挂断：回到桌面、锁屏时通话继续（麦克风类前台服务，通知栏可以回来或挂断）；通话中这个聊天的输入栏换成“回到通话”，主动聊天跳过这个联系人，到点的约定提醒留到通话结束后的下一次检查再发。用量分别记在聊天、语音识别和语音合成 |
| 通话消息（0.8.0 起） | 聊天里显示“通话时长 03:21”（正在打时显示“通话中”），预览和搜索结果标“[通话]”。点进去是通话详情：开始时间、时长和结束原因，每一句的文字（识别失败、被打断、没合成出声音的标出来），可以播放完整通话（按顺序接着放各句，能暂停、从停下的地方接着放、拖到任意位置）或单独放一句。只保存说话的那几段录音和合成的语音（`files/calls`），删除通话、清空聊天、删除联系人时一起删；不能重新生成 |
| 长聊天 | Paging 3 + Room 分页，每页 40 条；有未读时定位到第一条未读，只标红点时定位到最新 |
| 看历史 | 收到回复不跳走，显示“↓ N 条新消息”，点击回到底部；自己发消息总是回到底部 |
| 搜索 | 全局搜联系人名称和聊天内容，也可在聊天信息里查找；点结果跳到消息并高亮 |
| 聊天信息 | 查找聊天记录、消息免打扰、置顶聊天、设置当前聊天背景、清空聊天记录（免打扰和背景 0.4.2 起） |
| 消息免打扰 | 只不弹这个联系人的回复通知；未读数、预览、回复和记忆照常。等待或投递较久时的“正在接收消息”后台提示不含联系人信息，不受影响 |
| 聊天背景 | 从相册选择，按聊天图片的规则压缩后存在本机，只在这个聊天显示，不发给模型；可更换或恢复默认，文件丢失时回到默认背景 |

### 联系人与模型

| 功能 | 说明 |
| --- | --- |
| 联系人 | 新建、编辑、删除；独立的服务商、模型、思考档位、温度、系统提示词、上下文上限、使用全局记忆、使用回复偏好（这两项 0.5.0 起，新旧联系人默认开启）、分条显示、自动记忆、主动聊天（0.6.0 起），以及消息发送类型、音色、语气和风格（0.7.0 起；默认使用全局设置和服务商的音色）；0.7.2 起回复偏好可以跟随全局、单独设置或不使用，语音合成和识别来源也可以单独选。详情页显示服务商、模型、思考强度和请求里实际生效的温度，从“朋友资料”进入编辑（0.4.1 是“编辑”按钮）；编辑页的系统提示词单独一页编辑，下面显示系统提示词合计占用，超过上下文上限一半时提醒 |
| 全局记忆（0.5.0 起） | 我 → 全局记忆：按类别 → 主题 → 条目整理关于你自己的信息，每条可单独开关、编辑、删除和调整顺序，删除有内容的类别或主题先确认。开启“使用全局记忆”的联系人每次请求都带上全部已启用条目（不额外调用模型挑选），**会发给每个开启它的联系人所用的服务商**；页面写明会发给哪些服务商、条数、字数和按汉字 1 token 估算的占用，可一键让全部联系人开启或关闭 |
| 服务商 | 固定顺序的预置：DeepSeek、火山引擎（豆包）、阿里云百炼（千问）、BigModel（智谱）、月之暗面（Kimi）、Xiaomi MiMo、MiniMax、硅基流动、OpenRouter（0.7.2 起；新加火山引擎和 MiniMax，智谱、Kimi 改名。0.7.1 及更早是 DeepSeek、阿里云百炼（千问）、智谱、Kimi、Xiaomi MiMo、硅基流动、OpenRouter）；另有自定义入口。预置只填写新连接，不覆盖已保存地址和名称。火山引擎用火山方舟（`ark.cn-beijing.volces.com/api/v3`）控制台的 API Key，和豆包语音的 Key 不通用；MiniMax 的思考开关写成 `thinking.type: adaptive / disabled`，并带 `reasoning_split`，让思考内容不混进正文。0.7.2 起百炼的预置改用业务空间专属地址（`{WorkspaceId}.cn-beijing.maas.aliyuncs.com`，要把 `{WorkspaceId}` 换成自己的业务空间 ID 才能保存；已保存的连接不动）。Base URL 只支持 https，请求不跟随重定向 |
| 模型配置 | 不内置型号目录。主动获取列表或手动添加 ID；缺失的用途、图片、思考、温度信息保持待确认，准备使用的模型才需补齐 |
| 参数规则 | 思考分不支持、开关、始终开启，档位按实际原生值配置；温度可调、固定或省略；模型可覆盖兼容字段并恢复继承 |
| 刷新与冲突 | 保留手动、已配置、已引用和默认模型，未返回只标记；被引用模型须先解除引用才能删除。只有这次保存新造成的冲突才要确认，请求前阻止无效参数 |
| 上下文预算 | 每个联系人 1000～200000 token（默认 4000），可直接输入或加减；系统提示词（0.5.0 起含全局记忆和回复偏好要求）、记忆和聊天记录合计不超过它，超出时丢弃最早的消息，这次等待回复的消息一定带上。系统提示词的顺序：全局记忆 → 人设 → 记忆 → 回复偏好要求 → 约定时间的写法（0.6.0 起，只对开启主动聊天的联系人） → 时间和昵称。估算不用分词库：DeepSeek 按官方比例（汉字 0.6、其他 0.3），其他服务商汉字按 1 |
| 长期记忆 | 未总结的消息超过可用预算 80% 时，把最早的一半总结成一条，单批最多 6000 token。0.7.1 及更早：记忆最多占预算 1/4，超出时把最早的一半合并。**0.7.2 起分两层**：核心记忆（每个联系人一条，记着现在仍然成立的重要事实）和近期记忆（按时间的一段段总结）；总结只记重要内容，没有值得记的就不生成；每次请求带的记忆合计最多约 1500 token（上下文上限较小时最多占 1/4，核心记忆的字数要求也随之缩短，超出时只带开头放得下的几行），不再随上下文上限增长；近期记忆超出约 800 token 时，最早的、没改过的几条和核心记忆一起交给模型，整理成新的核心记忆（多一次请求，计入记忆用量）；升级前积累的大量记忆在之后几次回复里陆续整理完。可查看、编辑、删除，老聊天不自动回溯，可手动分批总结，每个联系人可关闭 |
| 记忆模型 | 联系人 → 记忆：独立选择同服务商的模型和思考档位；未指定时跟随服务商默认，默认为空时回退聊天模型。同联系人串行，全局最多并行 2 个，只保存总结正文 |
| 用量统计 | 按天、按联系人查看 token 用量；记忆总结单独标出，0.6.0 起主动聊天也单独标出（含模型决定不发的请求），0.9.0 起翻译也单独标出；0.7.0 起语音合成按字数和秒数、语音识别按秒数单独一行，不算进 token（0.7.1 的系统语音合成和离线识别在手机上进行，不计入）；清空聊天不影响统计 |
| 语音服务（0.7.0 起） | 我 → 语音消息（“我 → 模型服务”里的“语音合成”“语音识别”两行也进这里）：消息发送类型的全局默认；语音合成、语音识别**分别**选服务商（0.7.2 起每个联系人还可以单独选，包括系统语音和离线识别；单独选的用不了时不换成全局的，删掉那个服务商或离线模型后改回跟随全局）。预置 Xiaomi MiMo（合成 `mimo-v2.5-tts`、识别 `mimo-v2.5-asr`，聊天接口带音频的格式，合成可选预置音色）和硅基流动（识别 `FunAudioLLM/SenseVoiceSmall`，OpenAI 标准音频接口），也可自定义并选两种格式之一：聊天接口带音频（`/chat/completions`，按 MiMo 文档实现）或标准音频接口（`/audio/speech`、`/audio/transcriptions`）。Key 加密、只用 HTTPS、不跟随重定向，和大语言模型服务商相同；0.7.1 及更早不做试听。合成和识别的请求最多等 2 分钟（0.7.2 起智谱分段识别时每段各等 2 分钟）。服务商列表上面另有“本机”一组（0.7.1 起，见下一行），合成和识别默认都用标着“正在使用”的那一个（0.7.2 起联系人可以单独选，见上）。**0.7.2 起**：合成预置火山引擎（豆包）、阿里云百炼（千问）、BigModel（智谱）、Xiaomi MiMo、MiniMax、Fish Audio、硅基流动、OpenRouter，识别预置火山引擎（豆包）、阿里云百炼（千问）、BigModel（智谱）、Xiaomi MiMo、Fish Audio、硅基流动、OpenRouter，各用自己的请求格式（自定义仍只有两种通用格式；OpenRouter 识别用标准音频接口）；智谱一次只能识别 30 秒，更长的录音分段识别再拼起来；语气和风格要求对 MiMo、火山 2.0 音色、百炼、硅基流动 CosyVoice2 和 OpenRouter 上的 Gemini TTS、OpenAI、Fish Audio 模型生效。服务商页和联系人编辑页可以打开选音色页：按名称、ID、说明搜索，分组列出，可以试听（用 Key 合成一句话，可能计费，不计入用量统计）；MiMo、火山、百炼、智谱、硅基流动和 OpenRouter 上的 Gemini TTS、OpenAI 模型内置官方音色列表，MiniMax、智谱和硅基流动自己的音色用 Key 从服务商取，Fish Audio 到服务商搜索公开音色；列表可能不全，仍可手填 ID。这些格式只对着官方文档和本机模拟接口测过，没有调用过真实服务商 |

## 构建

需要 JDK（CI 用 21，维护者本机用 25）和 Android SDK（平台 37、构建工具 37）。`local.properties` 里写 `sdk.dir=Android SDK 路径`。如果下载依赖要走代理，给 `GRADLE_OPTS` 和 Gradle 命令都设置 http/https 的 proxyHost、proxyPort。0.7.1 起离线识别用的 sherpa-onnx AAR 不在 Maven 上，从它官方 GitHub Release 下载（`settings.gradle.kts` 里只对这一个模块开的仓库），构建前 `verifySherpaOnnx` 按 `app/build.gradle.kts` 里写死的 SHA-256 核对，不对就停止构建；所以构建时要能访问 GitHub。0.8.0 起语音通话判断说话用的 Silero VAD 模型（`silero_vad.onnx`，643,854 字节）也从 sherpa-onnx 的 GitHub Release 下载，`prepareVadAsset` 按写死的 SHA-256 核对后放进安装包的 assets，仓库里不提交模型文件。

```bash
./gradlew testDebugUnitTest   # 单元测试（含 Robolectric 截图测试）
./gradlew lintDebug           # 代码检查
./gradlew assembleDebug       # debug 包：包名 isomeria.aichat.debug，可与正式包同时安装
./gradlew assembleRelease     # release 包：需要正式签名（见下）
./gradlew assemblePerf        # perf 包：本地验证用，R8 开启、debug 签名，包名 isomeria.aichat.perf，不发布
```

`perf` 和 debug 包带测试工具（`app/src/testTools/`），release 不含。用 adb 生成虚构消息或触发一次崩溃：

```bash
adb shell am start -n isomeria.aichat.perf/isomeria.aichat.testtools.TestToolsActivity --es action seed --ei count 10000
adb shell am start -n isomeria.aichat.perf/isomeria.aichat.testtools.TestToolsActivity --es action crash
```

0.6.0 起另有 `proactive_run`（立即运行一次主动聊天检查：不掷概率，其余条件和额度照常，会调用模型）和 `proactive_state`（查看状态）。

0.7.0 起，debug 和 perf 包的应用私有目录里有 `files/test-voice-input.wav`（16 kHz 单声道 16 位 WAV）时，按住说话和录音转文字用这段音频代替麦克风（按实际时长读入，不录手机周围的声音）；release 里这个开关是关的（`TEST_TOOLS` 为 false），不会读这个文件。0.8.0 起语音通话同样可以用 `files/test-call-input.wav`（“说话—静音—说话”）代替麦克风：不在听的时候这段音频停在原处，下一次开始听接着往下放；每一轮各段的耗时（识别、模型首字、首次出声）在 debug 和 perf 包里以 `CallTiming` 标签写进 logcat，不含内容。放文件的方法：先 `adb push` 到 `/data/local/tmp`，再用 `adb shell run-as isomeria.aichat.debug cp` 复制到 `files/` 下，用完删掉。perf 包不能 run-as：0.9.0 起先 `adb push` 到 `/sdcard/Android/data/<包名>/files/`，再用测试工具的 `import_call_audio` 操作复制进 `files/`（`target=call` 是通话用的 `test-call-input.wav`，默认；`target=voice` 是按住说话用的 `test-voice-input.wav`；只收 16 kHz 单声道 16 位 WAV；`remove=true` 删掉，回到用麦克风），这个操作只在 debug、perf 包里有。`tools/mock_llm.py` 0.7.0 起也模拟两种通用格式的语音合成和识别（`--tts-mode` / `--asr-mode` 取 `ok`、`fail`、`empty`、`timeout`、`fail-once`）；0.7.2 各家的格式只在 JVM 测试里用 MockWebServer 模拟，`mock_llm.py` 没有。

新页面的浅色/深色截图：`./gradlew recordRoborazziDebug`。如果 Hilt 生成文件与 lint 并发分析冲突，先 `./gradlew --stop`，再为同一套验收加 `--no-parallel --max-workers=1`；不能把分析器崩溃当作 lint 通过。

## 正式签名

每个版本必须用同一个密钥签名，否则无法覆盖安装；卸载重装会清空全部本地数据。

本地签名读取根目录的 `keystore.properties`（已在 `.gitignore` 里，绝不提交）：

```properties
storeFile=keystore/aichat-release.jks
storePassword=...
keyAlias=aichat
keyPassword=...
```

**`keystore/aichat-release.jks` 和 `keystore.properties` 必须一起备份到至少两个独立位置。**

GitHub Actions 从仓库 Secrets 读取签名，需要配置：

| Secret | 内容 |
| --- | --- |
| `AICHAT_KEYSTORE_BASE64` | `base64 -w0 keystore/aichat-release.jks` 的输出 |
| `AICHAT_KEYSTORE_PASSWORD` | keystore 密码 |
| `AICHAT_KEY_ALIAS` | `aichat` |
| `AICHAT_KEY_PASSWORD` | 密钥密码 |

## 发布

1. 在 `app/build.gradle.kts` 里改 `appVersionName`（versionCode 按「主版本×10000 + 次版本×100 + 修订号」自动计算），和代码在同一个提交里
2. 在 `docs/release-notes/` 下写 `v<版本号>.md`，App 内更新弹窗会直接显示它
3. 公开分支不带 `docs/audits`、`docs/validation` 等测试证据；分支 CI 通过后再合并到 main
4. 推送 tag `v<版本号>`：`release.yml` 会核对 tag 与 versionName、跑单元测试、构建签名包、生成 `AIChat-<版本号>.apk` 和 `.sha256`，并创建正式 Release（不是 Pre-release）；R8 的 `mapping.txt` 存为 CI 产物，用来还原崩溃日志，不放进 Release，有保留期限

不要把 debug 包发到 Release：debug 包与 release 包签名不同，互相不能覆盖。

## 开发约定

- 新功能在 `feature/功能名` 分支开发，CI 通过后合并回 main；提交信息前缀 `feat` / `fix` / `refactor` / `docs` / `test` / `chore`
- 依赖版本统一放在 `gradle/libs.versions.toml`
- 界面文字全部放 `strings.xml`（`StringResourceGuardTest` 检查）；颜色、尺寸、字号只从 `ui/theme`（`WeTheme.colors / dimens / typography`）取
- 详细日志只在 debug 包输出；任何包都不记录 API Key 和消息正文
- 每次改表：数据库版本号 +1、写迁移脚本、用 `app/schemas` 里的 schema 文件做迁移测试

```
├─ ui/theme        微信风格主题：颜色、尺寸、字号
├─ ui/components   通用组件：顶栏、Tab 栏、头像、气泡、输入栏、列表行、对话框、菜单、表情面板
├─ feature/        main · chatlist · chat · chatinfo · call · contacts · contactedit · memory · globalmemory · replyprefs · proactive · voice · me · favorites · settings · usage · backup
├─ navigation      路由与页面切换
├─ core            纯逻辑：时间显示、链接识别、分条拆分、回复节奏（拆条、标点、间隔）、上下文拼装与预算、记忆策略、主动聊天的判断（免打扰时段、上限、暂停、概率、约定标记）、语音回复的类型和分段、通话的说话判断和分句、通话在上下文里的展开（0.8.0）、复制的文字格式和翻译方向（0.9.0）、用量汇总、拼音分组
├─ di              Hilt 依赖注入
├─ data/db         Room 表与 DAO
├─ data/repo       仓库层（页面只依赖这里）
├─ data/llm        模型服务接口：OpenAI Chat Completions、连接预置、能力/参数规则、兼容编码及 legacy 请求体、智谱错误码（0.7.2）
├─ data/memory     长期记忆：自动总结、合并（0.7.2 起整理核心记忆），后台任务
├─ data/reply      后台等待回复、待投递消息的投递、主动聊天的检查和约定提醒（都是 WorkManager 任务）与通知；语音的识别和合成流程（VoicePipeline）
├─ data/voice      语音服务接口（0.7.0 两种通用格式，0.7.2 起另有各家的格式）、预置、WAV、录音 / 编码 / 播放（接口和 Android 实现）、后台播放服务；系统语音合成、离线识别引擎、模型下载和后台下载任务（0.7.1）；内置音色列表、从服务商取音色、试听、长录音分段和 pcm 包装（0.7.2）；通话的麦克风、说话判断（Silero VAD）和放音（0.8.0）
├─ data/call       语音通话（0.8.0）：通话流程、通话中的请求、通话记录、前台服务
├─ data/settings   MMKV 设置
├─ data/crypto     Android Keystore 加密
├─ data/backup     导出与恢复（格式、整文件加密容器、密码加密、迁移）
├─ data/logs       本地崩溃日志（不依赖 Room 和 MMKV）

```

仓库其他目录：`app/schemas`（Room schema）、`app/screenshots`（截图基线）、`tools/`（`generate_emoji.py` 生成表情列表，`mock_llm.py` 是本机模拟接口）。
