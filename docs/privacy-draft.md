# 智信 AIChat 隐私说明（草稿）

状态：草稿，内容对照 0.4.1 的代码，1.0.0 时定稿。每新增一个要连接的服务器或一类本地数据，都在这里记一笔。这里只描述已发布版本的实际行为；未来版本的事项集中放在文末“待定稿”。

## 概述

智信没有账号系统，也没有开发者服务器。App 不收集统计数据，不做崩溃上报，不放广告，也不会把数据上传给开发者。

数据保存在手机上。只有下文“离开手机的数据”列出的情况，内容才会发到别处，其中聊天内容只发给用户自己配置的模型服务商。

## 保存在手机上的数据

| 数据 | 位置 | 保护方式 |
| --- | --- | --- |
| 联系人、会话和草稿、聊天记录、记忆、用量统计、服务商和模型配置 | 应用私有目录的 Room 数据库 | 系统的应用隔离和全盘加密；App 没有另外加密 |
| API Key | 数据库的服务商配置表 | Android Keystore 加密后存放 |
| 聊天图片、头像 | 应用私有目录 `files/images`、`files/avatars` | 系统的应用隔离和全盘加密 |
| 设置（深色模式、字体大小、昵称、头像路径、通知选项、更新检查状态、最近使用的表情、键盘高度） | 应用私有目录的 MMKV | 系统的应用隔离和全盘加密 |
| 崩溃日志 | 应用私有目录 `files/logs`，最多 20 份 | 系统的应用隔离和全盘加密；内容见下 |

临时文件：

| 文件 | 位置 | 什么时候清除 |
| --- | --- | --- |
| 分享崩溃日志时的副本 | 应用缓存 `cache/crash-exports`，只有一份 | 下次分享时覆盖；清理缓存或清空崩溃日志时删除 |
| 恢复前的快照：当前全部数据，API Key 仍是 Keystore 密文 | 应用私有目录 `files/backups` | 恢复成功后立即删除，删除失败时页面会提示；恢复失败时保留，必要时用它回滚 |
| 恢复时的文件副本和解密临时文件 | 应用缓存 `cache/restore` | 恢复结束即删除，下次启动也会清理 |
| 下载的更新安装包 | 应用缓存 `cache/updates` | 校验不通过立即删除；下次启动或清理缓存时删除 |
| 拍照的原始输出 | 应用缓存 `cache/camera` | 下次拍照或清理缓存时删除 |
| 图片缓存 | Coil 的应用缓存目录 | 清理缓存时删除 |

系统自动备份已关闭（`allowBackup=false`），这些数据不会经系统备份离开手机。卸载 App 会清除全部本地数据。

**对外不能写成“数据已加密”：** App 自己加密的只有 API Key 和设了密码的导出文件。

## 崩溃日志的内容

每份包括：时间、App 版本、设备型号、系统版本、崩溃类型（Java/Kotlin、ANR、原生）和堆栈。

不包括：异常说明（message）、聊天内容、记忆、提示词、图片内容和 API Key。ANR 只保留本 App 主线程的调用栈；原生崩溃只记录类型和时间，不解析符号。

日志只保存在本机，App 不会自动上传。用户在日志详情点“分享这份日志”时，才会由系统分享给用户选择的 App。独立日志页不向其他 App 导出，桌面快捷方式由系统启动。

## 离开手机的数据

| 去向 | 什么时候 | 内容 |
| --- | --- | --- |
| 联系人所用的模型服务商 | 发送消息、重试、重新生成 | 系统提示词、这个联系人的记忆、当前日期时间和用户昵称、预算内的聊天记录、模型参数和 API Key；模型支持图片时，还包括最近 3 张图片的压缩原图。人设和记忆都为空时不发送系统提示词，时间和昵称也不发送 |
| 联系人所用的服务商（请求记忆模型） | 自动或手动总结记忆、合并记忆 | 联系人名称、用户昵称、要总结的聊天文字或要合并的记忆、模型参数和 API Key。图片只以文字“[图片]”代替 |
| 用户填写的服务商地址 | 用户点击获取模型列表 | API Key；不带聊天数据 |
| GitHub（`api.github.com` 和 Release 下载地址，下载时可能跳转到 GitHub 的文件服务器） | 启动时检查更新（24 小时最多一次，可关闭）、手动检查、下载更新 | 普通 HTTP 请求，不带聊天数据和 API Key；对方能看到设备 IP |
| 用户自己选择的位置 | 用户导出数据 | 备份文件，见“导出文件” |
| 系统相册 `Pictures/AIChat` | 用户在查看大图时点保存 | 这张图片 |
| 用户自己选择的 App | 用户分享崩溃日志 | 这一份日志 |

服务商收到数据后如何处理，由该服务商的隐私政策约束。

**API Key 的去向：** Key 只随请求发给它所属服务商当前配置的 Base URL，请求不跟随重定向。用户修改已保存服务商的地址时，已保存的 Key 会保留，之后发给新地址；0.4.1 没有提示，`main` 已改、尚未发布，随 0.4.2 发布后要先确认。恢复备份时，只有请求格式和完整 Base URL 都相同才算同一个服务商，才会复用本机已保存的 Key。

**通知：** 回复到达时，通知内容由系统显示。关闭“内容预览”后，通知只显示“发来一条新消息”。

## 导出文件

- 不设密码：普通 zip，拿到文件的人都能打开聊天记录和图片。API Key 不导出。
- 设密码：整个文件用 AES-256-GCM 分块加密，密钥由密码经 PBKDF2-SHA256（31 万次）派生。忘记密码无法恢复。
- 包含 API Key 时必须设密码。

## 权限

| 权限 | 用途 |
| --- | --- |
| 网络（`INTERNET`） | 连接用户配置的服务商和 GitHub |
| 通知（`POST_NOTIFICATIONS`） | 回复到达时提醒 |
| 前台服务（`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_DATA_SYNC`） | 等待回复时让请求在后台继续 |
| 安装应用（`REQUEST_INSTALL_PACKAGES`） | 应用内更新时拉起系统安装界面 |
| `ACCESS_NETWORK_STATE`、`WAKE_LOCK`、`RECEIVE_BOOT_COMPLETED` | 由 WorkManager 依赖库加入，用于调度后台任务 |

相册和拍照使用系统选择器和系统相机，不申请存储和相机权限。文件导入导出使用系统文件选择器，保存图片到相册也不需要存储权限。
